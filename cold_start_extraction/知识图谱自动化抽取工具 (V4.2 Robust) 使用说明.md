# 知识图谱自动化抽取工具 (V4.2 Robust) 使用说明

## 1. 功能定位

本工具（`extract_V4.2_Robust.py`）用于“图谱冷启动/批量扩充”场景，支持 **并发处理**、**断点续传** 与 **过程性保存**，便于长时间批处理任务稳定运行。

它主要用于以下场景：

- **图谱冷启动**：在仅有产业链骨架的情况下，通过批量读取非结构化文本，自动填充实体与关系。
- **批量扩充**：当现有图谱规模较小，需要导入大量历史文档进行扩充时。
- **长时任务**：支持断点续传与过程性保存，适合处理耗时较长的大规模数据清洗任务。

## 2. 输入文件准备 (Input Data)

脚本运行依赖两个核心输入文件。默认情况下（按本仓库交付设置），输入/输出文件均位于脚本同级目录：`cold_start_extraction/`。

### 2.1 产业链骨架文件 (必需)

- **文件名**：`segment_mapping_input.json`
- **作用**：定义知识图谱的骨架结构（产业链环节），确保抽取出的实体能准确挂载到指定的环节上。
- **格式**：JSON 文件
- **数据结构**：
  - 采用三级嵌套结构：`一级环节 (宏观) -> 二级环节 (中观) -> [三级环节 (微观列表)]`
  - **Level 1 Key**: 上游/中游/下游或宏观分类（如 "上游基础层"）
  - **Level 2 Key**: 具体的产业环节（如 "算力调度"）
  - **Level 3 List**: 该环节下的细分关键词或技术点列表（如 "HPC", "算力租赁"）

**文件内容示例**：

```
{
    "上游基础层": {
        "算力调度": [
            "HPC",
            "算力租赁",
            "原子级科学计算",
            "数据底座和共性能力建设"
        ],
        "基础大模型": [
            "生成式AI",
            "AIGC",
            "医疗AI"
        ]
    },
    "中游技术层": {
        "模型推理平台": [
            "推理框架",
            "专家系统"
        ]
    }
}
```

### 2.2 待抽取数据文件 (必需)

- **文件名**：`new_data_upload.xlsx`
- **作用**：提供原始的非结构化业务文本数据，作为大模型抽取的信源。
- **格式**：Excel 工作簿 (.xlsx)
- **列名要求**：
  - **必需列**：`正文` (脚本将读取此列的每一行文本进行分析)
  - **建议列**：`标题`, `发布时间` (辅助人工核对，脚本逻辑主要依赖正文)

**Excel 结构示例**：

| 文档ID  | 标题                    | 发布时间   | **正文**                                                     |
| ------- | ----------------------- | ---------- | ------------------------------------------------------------ |
| 6904... | 中兴通讯前三季度业绩... | 2025-10-29 | 新浪科技讯...报告显示，1-9月，公司实现营收1005.2亿元...算力业务营收同比增长180%... |
| 7812... | 英伟达GTC大会详解...    | 2025-03-18 | 老黄还亲自详解：AI到底是什么？在GTC大会上...                 |

> **注意**：脚本会自动跳过 `正文` 为空或字符数过短（<5字符）的行。

## 3. 运行环境与配置

### 3.1 环境要求

- **Python 版本**：建议使用 **3.10.19**（与主系统一致，已验证可用）
- **操作系统**：Windows / macOS / Linux 均可

### 3.2 依赖安装

如已按主系统文档 `DEPLOYMENT.md` 使用 `environment.yml` 创建 conda 环境，则无需为本工具单独安装依赖。

如需单独部署本工具，也建议优先使用项目根目录的 `environment.yml`：

```bash
conda env create -f environment.yml
conda activate <environment.yml 里的 name>
```

说明：
- 环境名以 `environment.yml` 的 `name:` 为准；如已存在同名环境，可用 `conda env update -f environment.yml --prune` 更新。
- `environment.yml` 未固定 `torch/torchvision` 版本；如需使用 RAG/向量化相关能力（如 `sentence-transformers`），请根据部署机的 CPU/GPU/CUDA 条件选择并安装合适的 PyTorch。

### 3.3 模型接口配置

请确保项目根目录下存在 `llm_client.py`，并已正确配置大模型的 API Key、Base URL、模型名等参数。脚本会自动引用其中的 `LLMClient` 进行调用。

说明：
- 本脚本已做“导入路径兜底”，会优先使用项目根目录的 `llm_client.py`。
- 若 `cold_start_extraction/` 目录内存在同名 `llm_client.py`，也不会作为默认调用来源（以根目录为准）。

## 4. 运行与输出

### 4.1 启动命令

在完成上述文件准备和环境安装后，在终端执行：

```
python cold_start_extraction/extract_V4.2_Robust.py
```

### 4.2 运行过程

1. **初始化**：脚本会自动加载 `segment_mapping_input.json` 构建骨架。
2. **断点检查**：如果目录下存在 `processing_checkpoint.json`，会自动跳过已处理的批次。
3. **抽取中**：控制台将显示进度条，以及当前的抽取速度。

### 4.3 结果输出

脚本运行完成后，将在当前目录生成以下文件：

- **`full_industry_knowledge_graph.json`**：最终生成的图谱文件（包含节点与关系），可直接用于前端可视化或后续分析。
- **`failed_records.json`**：处理失败的数据记录（如有）。
- **日志文件**：`system_run_*.log`，记录详细的运行过程。
- **`processing_checkpoint.json`**：断点状态文件（用于续跑；任务完成后如需彻底重跑可删除）。

## 5. 与主系统衔接（将 full 图谱用于前端/后端）

本仓库的 Web 系统运行时读取/写入的“图谱主库”固定为：

- `static/data/graph_data.json`

因此，当冷启动脚本产出 `full_industry_knowledge_graph.json` 后，如需在本项目的前端/后端中使用该图谱，请按以下步骤替换主库文件。

### 5.1 替换位置与命名

1) 备份当前主库（建议）  
   将 `static/data/graph_data.json` 复制一份到 `backups/`（或自行备份到其他位置）。

2) 替换主库文件  
   把冷启动产出的 `full_industry_knowledge_graph.json` 拷贝到 `static/data/` 目录下，并改名为：

   - `static/data/graph_data.json`

3) 重启后端并刷新前端  
   - 重启 `backend_server.py`
   - 浏览器图谱页点击“刷新图谱”，或强制刷新（Ctrl+F5）

### 5.2 格式要求（关键）

替换后的 `static/data/graph_data.json` 顶层必须包含两个列表字段：

- `nodes`
- `relationships`

且每条关系的 `source/target` 必须能在 `nodes` 中找到对应节点。

> 说明：根目录下的 `graph_data.json` 为示例/参考文件；系统实际运行时默认读取与写回的是 `static/data/graph_data.json`。
