# 产业报告 Agentic RAG 第二阶段交付说明

日期：2026-10-16。第一、第二阶段已实施；第三、第四阶段尚未开始。

## 这次新增什么

系统在初次检索后，逐项判断章节需要的证据是否得到支持。每项判断保留具体原因，并将支持依据绑定到实际检索片段和逐字原文。只针对未解决的需求补查一次，再把证据、缺口和写作限制交给正文生成器。

流程为：

```text
章节初始检索（最多三个子问题）
  → 逐项评估证据
  → 对明确缺口补查一轮（最多两个新查询）
  → 有新增片段时再次评估，无新增则停止
  → 资料分配后恢复关键支持片段
  → 绑定统一引用编号
  → 正文按证据包及写作限制生成
```

## 证据判断与停止行为

- `supported`：存在回答需求的原文支持，必须关联真实片段与逐字引文。
- `insufficient`：当前完整展示的片段不足以支持需求。
- `conflicting`：保留至少两段冲突原文；先区分对象、时间、单位和口径。
- `unknown`：输入被截断、缺少明确时间或无法作出可靠判断；不自动当作充分。
- 原文服务失败且没有有效片段时记为 `unavailable`，不通过改写问题反复重试。
- 评估模型异常或输出无效时记为 `failed`，需求保持无法判断，不凭空生成补查。

旧的“不同资料来源少于三个就补查”逻辑及其辅助函数已移除；单个初始问题、固定查询回退和多问题执行都使用统一预算。最多三个初查加两个补查，补查不触发下一轮。

重复查询、没有可执行新查询、没有新增候选片段或达到一轮上限时停止。成功但空召回可根据章节具体需求形成有限补充查询；不会将检索错误伪装成空结果。

本阶段使用模型作语义判断，程序校验需求编号、允许路径、原文身份和逐字引用。逐字引文校验不能独立证明语义判断正确；正文生成后的声明支持核对仍属第三阶段。

## 分配与写作衔接

章节证据包 `evidence_pack` 包含各项需求状态、支持片段、资料冲突、未解决项和写作限制。

资料分配优先恢复仍在候选池中的关键支持片段，并保持每节证据容量。容量不足以保留完整支持时，相应需求降为无法判断，写作限制同步更新；不会重新进入补查循环。

证据包在资料分配后绑定报告级 `[C数字]`。同一份资料多个片段仍复用同一引用编号。正文生成同时接收原文上下文及证据包，明确遵守未解决项和证据边界：

- 排名、市场份额、出货量或产能缺乏可比依据时，改为公开产品和动态比较。
- 未确认的政策名称、日期和条款不写成已核实事实。
- 冲突数字保留来源、时间和口径，不擅自挑选一个数字。
- 图谱线索与原文事实分开，风险与建议区分事实依据和推断。

同步和流式流程共用实现，写作决策异常时仍保留证据包。自动合并小节保留来源证据包并传给正文；删除或合并说明也保留相关包。当前报告历史沿用完整写作任务保存，新界面展示仍按第四阶段实施。

## 限制与下一步

证据评估只针对本次召回并展示的片段，不能据此宣称全库或全网没有相应资料。原文输入有预算限制；截断、遗漏会保留为无法判断。时间要求进入查询并参与语义判断，尚未新增底层硬日期过滤。

真实样例仍遇到一次现有写作决策校验失败，采用备用决策完成正文，警告未隐藏。摘要文件合并协调和正文警告，因此同一警告可出现两次。

本次样例增加了排名要求并执行更多查询，与第一阶段约75秒的样例不能直接进行耗时差值归因。当前约198秒是单例实测，不代表稳定的平均耗时。

第二阶段形成了第一次业务交付所需的“规划—检索—评估—补查—约束写作”闭环。第三阶段再针对已经写出的数字、排名、政策和企业关系逐项核对实际引用，并接入现有局部修正机制。
