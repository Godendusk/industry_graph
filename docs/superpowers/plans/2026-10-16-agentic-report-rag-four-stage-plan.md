# 产业报告 Agentic RAG 四阶段实施规划

> 日期：2026-10-16。状态：四阶段技术实施与验证已完成（2026-10-16）；业务内容仍需使用方确认。
> 执行方式：按阶段逐项实施；使用 superpowers:executing-plans 跟踪任务。每阶段完成行为验证和真实样例核对后，再进入下一阶段。

**目标：**在已有 Hybrid v2 与 GraphRAG 基础上，实现章节检索规划、证据缺口驱动的补检索，以及正文关键事实与引用核对。

**架构：**现有报告协调器负责小节调度、并发、资料分配与引用登记；新增章节编排能力负责查询计划和证据判断。正文核对接入现有审阅与局部修改流程，摘要使用最终正文。

**技术基础：**Python、现有 LLM 调用与结构化输出工具、Hybrid v2、行业图谱、现有报告前端与 Word 导出。第一版使用项目现有能力实现有界工作流，不预设增加 Agent 框架依赖。

## 1. 项目范围与当前基础

本次只升级产业报告生成，智能问答不改动。已移除的 legacy、compare 与旧检索自动回退不恢复。

2026-10-16 阅读当前代码后，规划建立在以下接口上：

| 现有位置 | 已承担的职责 | 本次接入方向 |
| --- | --- | --- |
| `report_generation/coordinator_agent.py` | 小节检索、图谱扩展、资料分配、引用登记，支持同步和流式流程 | 在小节检索处接入计划与证据评估，两种入口使用同一实现 |
| `report_generation/external_rag/retriever.py` | 按行业调用 Hybrid v2 | 复用检索入口 |
| `report_generation/graph_retriever.py` | 行业图谱导航 | 按章节问题调用 |
| `report_generation/external_rag/graph_query_expansion.py` | 图谱关键词候选检索 | 复用，不额外复制一轮相同扩展 |
| `report_generation/external_rag/graph_evidence_retrieval.py` | 图谱关联原文解析与候选合并 | 保留原文身份与证据适用范围 |
| `report_generation/material_allocator.py`、`citations.py` | 跨章节资料分配、统一引用 | 分配后保留关键支持片段，统一登记新增资料 |
| `report_generation/review_agent.py` | 重复审查、证据疑点提示、最小片段修改与复核 | 扩展关键声明核对，复用修改流程 |
| `report_generation/body_agent.py`、`summary_agent.py` | 正文与摘要生成 | 接收写作约束，摘要基于最终正文 |

特别注意：协调器已有“不同资料来源少于三个时补查”的逻辑；审阅器已有证据提示，但证据输入会截断或省略。这两项必须纳入新流程，不能将已有补查之外再叠加无限补查，也不能将未展示证据误判为原资料不存在。

## 2. 总体流程与交付节点

```text
任务卡与已确认大纲
  → 现有协调器按小节调度
  → 章节检索规划
  → Hybrid v2 / 图谱辅助检索
  → 证据评估与一次针对性补查
  → 资料分配、关键支持片段保留、统一引用
  → 正文生成
  → 关键事实核对与现有审阅修正
  → 摘要、结论、导出
```

实施单位采用现有 `outline_id` 对应的正文小节，界面仍以用户熟悉的章节展示。第一版不新增报告总规划 Agent。

| 阶段 | 目标 | 交付节点 |
| --- | --- | --- |
| 1 | 会规划、会调用现有检索 | 可演示检索计划及资料来源 |
| 2 | 会识别证据缺口、会补查 | 第一次业务交付：Agentic 检索闭环 |
| 3 | 会核对关键事实并局部修正 | 可展示正文可信度改进 |
| 4 | 完成界面、端到端验收与说明 | 完整交付 |

## 3. 第一阶段：章节检索规划与执行

### 任务

- [x] 定义章节计划输入：报告需求、章节标题、写作重点、行业、时间要求和既有图谱/资料开关。
- [x] 生成一至三个初始子问题。每个问题明确要回答的内容、需要的证据、使用普通 Hybrid 或图谱辅助检索的原因。
- [x] 校验模型计划：问题不能为空，行业继承报告设置，问题数量有上限，工具只能选择当前已实现能力。复用现有 JSON 解析工具。
- [x] 复用当前检索与图谱增强流程执行子问题，保留材料、chunk/向量标识、原文片段和图谱证据范围；按已有标识去重，不增加哈希机制。
- [x] 接入同步和流式协调器；子查询先在小节内部顺序执行，跨小节并发沿用现有上限。
- [x] 规划失败时采用现有章节查询构造方式，并记录失败原因。有效结果保留，失败不能伪装为检索成功。
- [x] 将计划、实际查询、工具状态和耗时随写作任务保存，界面后续可读取。

### 文件安排

建议新增 `report_generation/agentic_rag/schemas.py`、`planner.py`、`executor.py`，以及包初始化文件。修改 `coordinator_agent.py` 的小节检索接入位置，复用 `structured_output.py`，不复制底层检索实现。

计划对象记录：`outline_id`、行业、时间要求、证据需求、子查询及策略。执行结果继续提供现有 `graph_retrieval` 与 `external_rag_retrieval`，新增计划和执行摘要，减少下游接口变更。

### 验证与完成标准

拟新增 `tests/test_agentic_report_planner.py`、`tests/test_agentic_report_executor.py`。验证复杂章节可拆解、简单章节不强制拆分、计划不能改变行业、异常计划可使用固定查询、同一片段不重复、同步和流式路径一致。

若测试发现跨行业调用或引用身份丢失，修正计划校验或合并逻辑后才能进入第二阶段。用一个真实竞争格局小节演示完整计划到正文的过程；此时不宣称已具备语义充分性判断。

## 4. 第二阶段：证据评估与目标化补检索

### 任务

- [x] 将章节需求转成具体证据要求，例如“企业代表产品”“某年订单”“政策适用对象”，避免用资料数量替代支持判断。
- [x] 对每项要求返回：有支持、支持不足、存在冲突、无法判断；关联具体原文片段和简短原因。工具失败另行记录。
- [x] 只对有明确缺口且能生成新查询的要求补查。默认最多一轮补查、最多两个补充子查询；初始最多三个子查询。
- [x] 将现有来源数量不足补查并入统一预算；不能让每个子查询继续隐式触发旧补查。底层图谱关键词查询、关联原文读取及模型调用也记录实际次数。
- [x] 查询重复、没有有效新证据或预算耗尽时停止，保留未解决缺口。
- [x] 形成章节证据包，包含需求与片段对应关系、冲突、写作约束和执行状态。
- [x] 分配资料时优先保留关键支持片段。分配后检查原绑定是否仍在；丢失时从已检索候选恢复，受容量限制无法保留时标为不足，不重新启动补查循环。
- [x] 把证据包和约束传入正文生成器，补查资料仍由统一引用登记处理。

### 按具体内容处理证据不足

| 内容 | 行为 |
| --- | --- |
| 背景、趋势 | 基于已有证据写作，区分观察与判断 |
| 企业、产品、关系 | 只写原文支持的关系；未绑定原文的图谱关系作为线索 |
| 政策名称、日期、条款 | 缺少依据的内容不输出为确认事实，列入待确认项 |
| 排名、份额、出货量 | 无比较依据时改写为产品布局或公开动态，不生成确定排名 |
| 冲突数字 | 核对对象、时间、单位和口径；无法解释则注明差异或暂不采用 |
| 风险、建议 | 明确事实依据与分析推断之间的区别 |

不设置“覆盖达到80%就通过”或模型自报置信分数。一个关键排名缺少依据，即使其他资料齐全也必须限制该排名表述。

时间要求区分资料发布日期和事件发生时间；允许使用更早的背景资料时明确其用途。未知日期标记为未确认；只有底层接口实际支持时才使用前置时间过滤。

### 文件安排与完成标准

新增 `agentic_rag/assessment.py`；扩展 `schemas.py`、`executor.py`。修改协调器现有补查逻辑和资料分配接入点，按需修改 `material_allocator.py`、`body_agent.py`。

拟新增 `tests/test_agentic_report_assessment.py`、`tests/test_agentic_report_budget.py`。覆盖：资料很多但不支持目标、补查无新增、来源冲突、图谱线索未绑定原文、预算不会叠加、分配后关键证据丢失、同资料引用复用。

完成标准：真实小节能展示“发现什么缺口—如何补查—新增什么证据—剩余哪些限制”，证据不足时正文遵循约束。达到第一次业务交付节点。

## 5. 第三阶段：关键事实与引用核对

### 任务

- [x] 优先抽取数字、年份、排名、政策条款、企业产品及合作关系等关键声明，保留正文中的准确位置。
- [x] 将声明与引用对应的实际片段逐项核对，输出支持、部分支持、不支持、冲突、无法判断及原因。
- [x] 同时保存报告级引用编号与片段标识；一份资料被引用不代表其中任意片段支持该声明。
- [x] 对输入截断、证据遗漏、语义含糊的情况返回无法判断，不能当成确定不支持。优先在已检索证据中按声明取片段，不另开自动补检索循环。
- [x] 接入现有审阅流程：合并需要修改的片段，检测重叠要求，由同一修改流程执行一次有界修正。
- [x] 修改只删除或收窄无依据的内容，保留独有事实、限定条件、计划/已实现状态及有效引用。
- [x] 修正后核对受影响的声明与引用；未解决、失败或发生信息损失时保留待确认状态，必要时使用现有恢复机制。
- [x] 摘要使用审阅后的正文，复用已有摘要一致性检查。局部重写后，相关核对结果失效并重新核对受影响内容。

### 文件安排

新增 `agentic_rag/verification.py`；扩展 `review_agent.py` 和相应结果数据。复用 `citations.py` 的编号检查与现有片段补丁机制。仅在接口确有需要时调整 `summary_agent.py`，避免重复建设摘要校验。

### 验证与完成标准

拟新增 `tests/test_agentic_report_verification.py`，并扩展现有审阅、局部重写、引用测试。用“供应商被写成最大供应商”“计划扩产被写成已经投产”“同一来源不同片段”“证据被截断”“核对失败”作为明确案例。

失败时分别修正声明匹配、事实状态保留、片段选择或状态处理。人工抽样核对误报和漏报；自动模型判断不能同时作为唯一验收答案。

完成标准：能识别有引用但没有对应支持的关键结论，修正不会损害其他事实，未核实内容不会显示为通过。

第三阶段交付与验证记录见 [阶段三交付说明](../../agentic-report-stage3-delivery-2026-10-16.md)。

### 验收与决策

| 核对内容 | 如何判断 | 未达到时怎么办 |
| --- | --- | --- |
| 关键问题覆盖 | 人工判断同一小节要求是否被有效回答 | 修正规划或检索路径 |
| 补查收益 | 新资料是否填补实际缺口并被有效使用 | 收紧补查触发条件或查询 |
| 声明支持 | 抽样比对声明与原文，包含误报、漏报 | 修正核对提示与证据选择 |
| 修改质量 | 关键限定、独有事实、引用是否保留 | 缩小自动修改范围，保留待确认 |
| 运行代价 | 记录总耗时、模型调用、检索次数与人工修改量 | 减少重复调用、精简子问题 |
| 链路完整性 | 同步/流式、历史、重写、摘要与导出状态一致 | 修复衔接后再交付 |

不预先承诺未测得的提升比例。真实对照应展示具体改善和退步案例；若关键事实质量变差，应修正后复测受影响场景，不能只凭运行成功交付。

第四阶段交付、实测耗时和已知限制见 [阶段四交付说明](../../agentic-report-stage4-delivery-2026-10-16.md)。双产业固定五节报告均已产出，来源抽样记录见 [真实验收记录](../../../evaluation/agentic_report/runs/reports-final-20261016/acceptance-summary.md)。这代表技术链路完成，不代表甲方已确认内容质量。

## 7. 工作原则与范围边界

- 每阶段按“定义行为样例—编写针对性测试—实现—验证—展示实际结果”执行；测试发现问题会改变实现时才运行。
- 每阶段单独整理变更和验证记录，便于审阅与恢复。落地前确认当时工作区状态，避免包含其他并行任务的修改。
- 规划失败回到当前固定检索方式；图谱失效可继续使用有效文档证据。所有检索失败时明确显示不可用，不能当成普通资料不足。
- 沿用现有模型配置、并发和请求控制，不为每个角色引入独立模型服务或第二套并发系统。
- 执行记录只保存计划、实际调用、证据关联、简短决策依据和状态，不要求保存模型内部思考。
- 第一版不做新图谱构建、多模态、表格新引擎、排序训练、无限工具循环或新的总报告 Agent。
- 历史文档和迁移脚本中的 legacy 字样不作为本次清理任务；只有仍误导当前使用的说明才随相关改动修正。
