# Remove legacy report retrieval

用户已批准上一轮提出的清理范围，本轮直接在现有工作区实施，保留其他进行中的改动。

目标：八产业报告检索只走现有 hybrid；删除 legacy、compare、自动回退及模式配置。保留 hybrid 内部召回/重排容错。保留旧数据库和离线导入建库能力。

实施顺序：
1. 替换旧模式测试，覆盖旧环境变量不能改变 hybrid 路由、混合失败原样报错、产业隔离。
2. 删除检索分支及无调用的旧检索函数，清理 RetrievalConfig 的 mode/fallback 字段。
3. AI 摄取必须先完成 v2 写入，失败由现有摄取错误流程记录；旧库写入暂保留作为离线源，移除 v2 双写开关。
4. 更新当前操作文档；历史验收记录保留历史事实并标注现状。
5. 运行检索路由、混合流水线、摄取、索引和报告消费者测试。若失败则依据具体失败修复。运行真实 AI 检索确认 768 维索引可用，不改写现有库。

验收：不再返回 legacy/比较结果；v2 出错不换库；AI 摄取不能在 v2 写入失败时声明成功；现有混合召回及引用格式保持有效。

完成记录：路由、混合流水线、索引、摄取和报告消费者相关测试 334 passed、169 subtests passed。八产业真实检索全部通过双路召回、重排分数、产业隔离及来源信息检查，结果见 report_generation/outputs/hybrid-only-cleanup-20261015/acceptance.json。定点代码审阅未发现明确可达回归。未删除数据库文件，未重启实际后端服务。
