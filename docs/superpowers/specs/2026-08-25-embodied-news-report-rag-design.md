# 具身智能专题资讯报告 RAG 设计

> 状态：阶段一历史设计，已完成。本文保留最初“最新 100 条资讯”验证范围；全量向量库现状与报告验收方案见 [2026-09-15-embodied-full-rag-report-validation-design.md](./2026-09-15-embodied-full-rag-report-validation-design.md)。

## 目标

第一版打通具身智能专题资讯到产业报告生成的链路。首批只抓取最新 100 条资讯，报告章节结构沿用现有人工智能报告模板，不设计具身智能专属章节。

## 范围与边界

- 新建独立 Chroma 持久化目录 `RAG/vector_db_embodied/`。
- 创建单一集合 `embodied_news`，使用现有 `bge-base-zh-v1.5` 生成 768 维向量。
- 具身智能通过行业参数路由到新集合；人工智能继续使用现有五类资料库。
- 图谱按行业读取，具身智能使用 `static/data/embodied/graph_data.json`。
- 不复制人工智能的五类集合，不做全量资讯同步、定时调度或管理页面。

## 数据流

```text
专题资讯列表接口
  -> 前 100 条资讯
  -> 详情接口
  -> 正文清洗与 300-500 字符分段
  -> bge-base-zh-v1.5
  -> RAG/vector_db_embodied/embodied_news
  -> 行业路由检索
  -> 现有报告 Agent 与具身智能图谱
  -> 现有报告模板
```

## 向量数据模型

每个正文片段写入一条 Chroma 记录：

```json
{
  "id": "<source_id>:<chunk_index>",
  "document": "标题\\n摘要\\n正文片段",
  "metadata": {
    "source_id": "原资讯 ID",
    "subject_id": "2043590589800853505",
    "title": "资讯标题",
    "publish_date": "发布日期",
    "source": "来源",
    "url": "原文地址",
    "chunk_index": 0,
    "total_chunks": 4
  }
}
```

建库使用 `upsert`。同一资讯的片段 ID 稳定，重复运行不会重复增加向量。空正文跳过；详情失败单条记录并继续处理；最终输出列表数、详情成功数、跳过数、片段数和 Chroma 总数。

## 报告检索路由

外部 RAG 检索入口增加行业路由：

- `industry="embodied"` 查询 `RAG/vector_db_embodied/embodied_news`。
- `industry="ai"` 保持现有人工智能五库逻辑。
- 不支持的行业返回明确错误，不静默回退到人工智能。

大纲、协调、正文和摘要 Agent 继续使用现有生成流程，仅动态传递具身智能行业名称、外部检索结果和图谱上下文。

## 异常处理

- 接口网络错误或鉴权失败：建库立即停止，并标记失败。
- 单条详情获取失败：记录资讯 ID 与原因，继续其余资讯。
- 向量写入失败：记录批次与异常，最终标记为部分失败。
- 仅在流程完成且至少写入一条有效片段后生成成功状态标记。

## 验收标准

使用以下问题分别查询 Top 5，并检查标题、日期、来源和正文片段：

1. `具身智能人形机器人有哪些最新进展？`
2. `具身智能产业链有哪些核心环节？`
3. `具身智能相关政策支持有哪些？`

还需确认：

- `ai` 仍访问原人工智能资料库。
- `embodied` 不访问旧人工智能集合。
- 具身智能报告行业名称为“具身智能”。
- 报告外部依据来自 `embodied_news`。
- 图谱上下文来自具身智能图谱文件。
- 现有人工智能报告相关测试不回归。
