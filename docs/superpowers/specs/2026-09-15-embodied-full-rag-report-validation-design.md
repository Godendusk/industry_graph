# 具身智能全量 RAG 与报告验收设计

## 文档定位

本文是具身智能专题资讯 RAG 的第二阶段设计，承接第一阶段的最新 100 条资讯验证。当前数据摄入、向量化、本地存储和行业路由已经具备，本阶段不再建设数据库，目标是用真实全量库跑通第一份具身智能产业报告，并以可观察的检索证据判断报告链路是否可用。

本文记录的是 2026 年 9 月 15 日的本地运行快照。资讯数量和向量数量会随未来增量更新变化，不作为代码常量或长期不变的业务约束。

## 已知数据边界

全量摄入期间有三个异常页区域未完全写入。由于资讯持续新增，原页码在当前接口中已经发生偏移；通过接口记录与 Chroma `source_id` 对照，当前发现约 215 条资讯缺失，占全量资讯约 0.09%。一次补录尝试成功写入了部分缺失内容，但仍有异常记录无法编码。

本阶段接受该缺失比例，不再重跑全量摄入，也不以修复这些异常资讯作为报告验收的前置条件。报告测试若恰好需要缺失资讯，应记录为数据覆盖限制，不把它误判为检索算法或报告 Agent 故障。

全量任务完成后曾被再次启动，导致 manifest 被新运行覆盖。Chroma 数据库未被删除，已通过本地 collection 计数和真实语义查询验证。当前数据库本身是运行依据，旧 manifest 不作为全量完成证明。

## 当前数据流

```text
用户报告需求
  -> 识别 industry="embodied"
  -> 生成报告大纲和章节检索问题
  -> 查询 RAG/vector_db_embodied/embodied_news
  -> 返回标题、正文片段、发布日期、来源和原文地址
  -> 读取具身智能图谱上下文
  -> 协调各章节证据
  -> 生成正文、摘要与改写结果
  -> 按项目现有能力导出最终报告
```

数据库摄入接口不参与本阶段报告运行。生成报告不需要重新请求专题资讯接口，也不需要 `EMBODIED_ACCESS_TOKEN` 或 `EMBODIED_X_ACCESS_TOKEN`。

## 第一份测试报告

使用以下需求进行端到端验证：

> 生成一份具身智能产业发展报告，重点分析人形机器人技术进展、产业链结构、政策环境、主要企业、典型应用、商业化趋势及风险挑战，并尽量引用近期可靠资讯。

报告沿用项目当前报告结构。本阶段不提前设计具身智能专属固定模板；先观察现有大纲 Agent 能否根据需求形成合理章节，再决定是否需要行业专用章节约束。

## 执行设计

### 1. 入口与路由确认

先定位项目真实报告入口和调用链，不根据文件名推测运行命令。执行前确认：

- 行业参数为 `embodied`；
- 外部 RAG 的实际 collection 为 `embodied_news`；
- 图谱文件为 `static/data/embodied/graph_data.json`；
- 没有静默回退到人工智能资料库。

若任一条件不成立，先停止报告生成并修复路由，不使用错误数据生成一份表面完整的报告。

### 2. 小规模真实检索

在完整报告之前执行三类代表性检索：

1. `具身智能人形机器人有哪些最新进展？`
2. `具身智能产业链有哪些核心环节？`
3. `具身智能相关政策支持有哪些？`

每类至少查看 Top 5 的标题、发布日期、来源、URL、正文片段和距离。小规模检索用于确认数据库、模型、元数据和行业路由均能在当前机器上工作，不用于替代完整报告验收。

### 3. 完整报告生成

通过项目现有入口依次运行大纲、正文、摘要及最终导出。每个主要章节保留可追溯的检索依据，至少能够关联到资讯标题、发布日期、来源或 URL。若大模型凭据缺失，则继续完成所有本地检索和上下文构造验证，并明确报告缺少的环境变量；不得猜测或写入凭据。

### 4. 结果审阅

从以下方面审阅最终报告：

- 章节是否覆盖技术、产业链、政策、企业、应用、商业化和风险；
- 检索内容是否与当前章节主题一致；
- 时效性主题是否优先使用近期资讯；
- 事实、数字、企业事件和政策是否能追溯到来源；
- 是否出现大量重复新闻或同一来源垄断多个章节；
- 是否混入与具身智能无关的其他行业资料；
- 图谱内容与资讯证据是否被清楚区分；
- 章节之间是否存在明显重复或矛盾。

## 验收标准

第一份报告同时满足以下条件时，端到端链路判定为可用：

1. 本地查询打开 `embodied_news`，collection 计数为非零且向量维度为 768。
2. 三类代表性检索均返回与问题相关的具身智能资讯。
3. 完整报告调用使用 `industry="embodied"`，未访问人工智能旧集合。
4. 图谱上下文来自具身智能图谱文件。
5. 报告形成完整大纲、正文和摘要，并成功生成项目支持的最终文件。
6. 主要事实可以关联到检索结果中的标题、日期、来源或 URL。
7. 没有系统性跨行业污染、空章节或大面积无依据生成。
8. 具身智能相关测试通过，人工智能报告流程没有回归。

若报告能够生成但证据相关性、时效性、来源多样性或章节去重不理想，应将链路判定为“可运行、质量待优化”，并把具体问题转入下一阶段的检索评测，不在本阶段盲目调整参数。

## 输出物

本阶段应产生：

- 一份完整的具身智能产业发展测试报告；
- 报告文件的绝对路径；
- 每个主要章节使用的检索依据摘要；
- 一份简短质量评估，列出报告是否可用及最值得优化的三个问题；
- 与具身智能链路相关的测试结果及人工智能链路回归结果。

## 不在本阶段处理的内容

- 不重新抓取或重建全量向量库；
- 不继续修复少量异常资讯；
- 不开发定时任务或增量同步；
- 不推广到低空经济等其他行业；
- 不预先拆分具身智能多 collection；
- 不在看到第一份真实报告前调整 chunk 大小、检索权重或 reranker。

上述事项根据第一份报告暴露的问题另行设计和排期。
