# 原始资料 Hybrid-RAG 小样本评测设计

## 背景

主工作区的 `RAG/raw_docx_files/` 保存了人工智能产业原始资料；产业报告外部资料 RAG 逻辑则按政策法规、领导讲话、专家观点、企业案例、研究报告五类 collection 工作。原始 DOCX 本身没有可靠的五类 collection 元数据，因此需要先做可追溯的自动初分类，再用小样本验证新版检索链路，避免直接把混合资料全量写入索引。

## 目标

建立一套可重复运行的小样本评测流程，完成以下工作：

1. 从原始 DOCX 中按标题和正文规则自动初分类。
2. 对无法明确归类的资料标记为 `待复核`，不进入正式评测索引。
3. 从五类中各抽取约 10～20 篇，形成约 50～100 篇、带来源和分类依据的样本清单。
4. 结构化抽取正文、标题、章节和表格文本，并生成适合中文检索的 chunks。
5. 使用新版 `hybrid_v2` 链路比较 Dense、BM25、RRF、Cross-Encoder 重排各阶段效果。
6. 使用真实人工智能产业问题进行端到端检索测试，输出可审阅的召回、重排和证据结果。

## 非目标

- 本阶段不修改生产环境默认的 `legacy` 模式。
- 不删除或覆盖现有 `RAG/vector_db`、`RAG/vector_db1` 或用户已有未提交改动。
- 不把没有人工确认或无法明确分类的资料直接写入正式评测 collection。
- 不把自动分类结果当作最终业务标签；正式上线前仍需领域人员复核。

## 分类策略

分类器以文件名/标题和正文前若干段为输入，使用确定性关键词、标题模式和优先级规则，输出：

- `policy` / 政策法规
- `speech` / 领导讲话
- `expert_view` / 专家观点
- `company_case` / 企业案例
- `research_report` / 研究报告
- `review_required` / 待复核

每条分类记录必须保留：源文件相对路径、标题、分类、分类分数、命中的规则、正文长度、表格数量和处理状态。分类存在多个高分候选且差距不足时，统一标记为 `review_required`。规则应优先识别明确的文种或材料类型；一般性的行业分析、趋势观察和对运营商启示类文章默认进入研究报告候选，但低置信度时仍进入待复核。

## 样本构建

样本构建器从每个正式类别中选择 10～20 篇，默认目标为每类 15 篇。选择优先满足：

- 正文可成功抽取且长度达到最小阈值；
- 标题和正文均与人工智能产业相关；
- 文档长度和章节数量有一定分布，避免全部是短文或同一主题；
- 同名文件、重复文件和历史残留记录不重复进入样本。

输出一个 JSONL 清单和一份汇总报告。清单中的样本状态初始为 `auto_labeled`，人工核验后可改为 `approved` 或 `review_required`。只有 `approved` 样本可用于正式指标评测；`auto_labeled` 样本可用于管线冒烟测试，但不能作为最终效果结论。

## 文档抽取与索引

对 DOCX 使用结构化抽取：

- 保留段落顺序、标题层级和章节路径；
- 读取表格并转为带表头上下文的文本块；
- 记录 `source_file`、`material_id`、`title`、`library`、`classification_name`、`paragraph_index`、`section_path` 和 `content_type`；
- 使用现有 `retrieval_core.chunker.build_report_chunks` 生成 chunks；
- 索引写入独立的评测目录，不写入生产 `RAG/vector_db`；
- embedding、BM25 和重排模型均使用项目配置的本地模型；模型或依赖缺失时给出明确阻断信息，不静默降级为不可比的结果。

评测索引必须有独立的版本/READY 标记，并记录模型版本、chunker 版本、分类清单哈希和样本清单哈希，保证结果可复现。

## 检索对比

对每个测试问题分别保存以下结果：

1. Dense-only
2. Lexical/BM25-only
3. Dense + BM25 + RRF
4. RRF + Cross-Encoder rerank
5. 新版完整链路（包含业务调整和邻居扩展，如该阶段有可用实现）

每个结果保留候选的 `material_id`、`chunk_id`、资料类别、标题、章节、文本、各阶段分数和诊断信息。指标至少包括 Recall@5、Recall@10、MRR 和 nDCG@10，并按问题总体和五类资料分别统计。

## 测试问题与标注

初始问题覆盖运营商 AI 布局、端侧 AI、智算中心绿色化、DeepSeek/开源模型、AI Agent/智能体等主题。问题集采用 JSONL，每条包含问题、目标报告场景、相关资料或相关 material_id、人工审核状态。未审核问题只用于诊断，不用于正式指标结论。

## 端到端验证

对选定问题执行报告检索入口，确认：

- 查询解析能提取报告标题、当前章节和检索目标；
- 资料库软路由符合预期；
- 五类 collection/索引均能被正确访问；
- 召回结果经过融合和重排后仍保留可解释的证据元数据；
- 缺失 collection、模型或单阶段失败时，结果包含结构化 warning，不伪造成功；
- `legacy` 默认行为保持不变，`compare` 可同时返回对比信息，`hybrid_v2` 只读取独立评测索引。

## 产物

本阶段预期新增或生成：

- 分类清单：`evaluation/raw_docx_rag/sample_manifest.jsonl`
- 分类汇总：`evaluation/raw_docx_rag/classification_summary.json`
- 测试问题：`evaluation/raw_docx_rag/queries.jsonl`
- 评测结果：`evaluation/raw_docx_rag/results/`
- 独立评测索引：`RAG/indexes/raw_docx_eval_v1/`
- 可重复运行的样本构建、抽取、索引和评测脚本及测试

所有生成目录均与生产五库隔离；不覆盖已有 collection 或现有索引。

## 验收标准

- 五类中每类至少有 10 篇可处理样本，目标每类 15 篇；不足时报告实际数量并阻止正式指标评测。
- 待复核资料不会进入 `approved` 样本或正式评测索引。
- DOCX 段落和表格抽取可由单元测试验证，且至少抽查每类若干篇。
- 独立索引可以构建、发布 READY 并被新版检索链路读取。
- 检索对比结果包含五个阶段或明确记录不可用阶段的原因。
- 评测结果包含 Recall@5/10、MRR、nDCG@10，以及原始候选和重排后候选。
- 全过程不修改生产默认模式和用户已有未提交文件。
